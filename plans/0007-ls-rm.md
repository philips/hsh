# `hsh ls` and `hsh rm`

## Goal

Subcommands to list and clean up hsh sandboxes, following podman's
flags and semantics (`podman pod ls` — aliases ps/ls/list — and
`podman pod rm`). The main use case: a killed or crashed `hsh` leaves
its pod behind (the default flow removes the pod on exit, but SIGKILL or a
crash does not), and users need to find and remove those leftovers.

## What counts as a hsh sandbox

- Pods created by `hsh run`: named `hsh-<12 hex>` (random name for
  default launches, workspace hash for `--resume`).
- Pods labeled `hsh.workspace=<path>` (currently only `--resume` pods).
- Selection for `ls`/`rm`: pods whose name contains `hsh-` (matches
  both), cross-checked with the label when present. Podman's own filters
  work too: `podman pod ls -f name=hsh` and
  `-f label=hsh.workspace=<path>` (verified).
- Proposed small change: label **all** pods (not just `--resume`) with
  `hsh.workspace=<first mount source>` in `run`, so `hsh ls`
  always shows the workspace.

## `hsh ls`

Follow `podman pod ls` (verified flags: `--ctr-ids`, `--ctr-names`,
`--ctr-status`, `-f/--filter`, `--format`, `-l/--latest`, `--no-trunc`,
`-n/--noheading`, `--ns`, `-q/--quiet`, `--sort`; default sort "created").

Default output — podman's columns plus a `WORKSPACE` column (from the
label):

```
POD ID        NAME                   STATUS      CREATED       INFRA ID      # OF CONTAINERS   WORKSPACE
```

Flags:

- `-q, --quiet` — pod IDs only
- `-n, --noheading` — no header row
- `--no-trunc` — full IDs
- `--sort string` — created (default), id, name, number
- `-f, --filter stringArray` — podman filters, passed through
- `--format string` — Go template, passed through (the workspace is
  available as the pod label, e.g. `{{.Labels}}`)
- `--ctr-ids`, `--ctr-names`, `--ctr-status`, `--ns` — passed through
- `-l, --latest` — only the most recently created sandbox
- Optional convenience: `--workspace PATH` — filter by the
  `hsh.workspace` label (equivalent to
  `-f label=hsh.workspace=PATH`)

No `--all`: like `podman pod ls`, all hsh sandboxes are listed
(running and stopped).

## `hsh rm`

Follow `podman pod rm` (verified flags and semantics):

```
hsh rm [options] SANDBOX [SANDBOX...]
```

- Positional args: sandbox names or ID prefixes. Optional convenience: an
  arg that is an existing directory resolves to the sandbox labeled with
  that workspace.
- `-a, --all` — remove all hsh sandboxes
- `-f, --force` — stop running containers first (SIGTERM, then SIGKILL
  after `-t` seconds), then remove. Default: a sandbox with running
  containers is refused, exactly like podman ("running or paused
  containers cannot be removed without force" — verified).
- `-i, --ignore` — do not fail when a specified sandbox is missing
- `-t, --time int` — seconds to wait for stop before killing (default 10)
- `-l, --latest` — act on the most recent sandbox
- `--pod-id-file` — optional, low value; skip unless asked
- Session state: after removing a sandbox, also remove its session state
  directory (`$XDG_STATE_HOME/hsh/sessions/<hash>/`) if present — the
  CA and resolved secrets are meaningless without the pod. With `--all`,
  sweep all session state directories (full cleanup, including orphaned
  ones whose pod is already gone).

Semantics (podman): without `-f`, running sandboxes are refused; with
`-f`, containers are stopped then removed; `--ignore` suppresses
missing-sandbox errors; exit code is non-zero if any removal failed
(unless `--ignore`). Removing the sandbox of a currently running session
is allowed (with `-f`) — that is the "kill a hung sandbox" use case.

## Implementation sketch

- `internal/cli/ls.go`: `hsh ls` — run `podman pod ls` with the
  user's flags plus the hsh selection (name filter `hsh-`, or
  filter in Go for the default table to add the WORKSPACE column).
- `internal/cli/rm.go`: `hsh rm` — resolve args to hsh sandboxes
  (name/ID prefix match, or workspace via the label), run
  `podman pod rm` with the flags, remove session state dirs, report
  per-sandbox results.
- `internal/cli/run.go`: label all pods with `hsh.workspace`.
- `main.go`: register the subcommands, extend usage.
- `docs/architecture.md`: lifecycle section gains `hsh ls` /
  `hsh rm` (with examples: `hsh ls`, `hsh rm --all -f`).
- `test/functional.sh`: create leftover sandboxes (e.g. a `--resume`
  sandbox whose host process is killed, or a manually created pod named
  `hsh-test-*`), then: `ls` shows them with the workspace, `rm <name>`
  removes one, `rm --ignore` on a missing name succeeds, `rm` without
  `-f` refuses a running sandbox, `rm -f` removes it, `rm --all` removes
  the rest.

## Verification

1. `hsh ls` on a host with leftover sandboxes lists them (name,
   status, workspace) and nothing else; `-q`, `-n`, `--no-trunc`,
   `--sort name`, `--filter`, `--format` behave like podman.
2. `hsh rm <name>` removes a stopped sandbox; `hsh rm` on a
   running sandbox fails without `-f` and succeeds with `-f`.
3. `hsh rm --ignore <missing>` exits 0; without `--ignore` it fails.
4. `hsh rm --all` removes every hsh sandbox and sweeps session
   state; non-hsh pods are untouched.
5. `hsh rm <workspace-path>` resolves via the label.
6. Session state dir is removed with its sandbox; a later `--resume`
   regenerates the CA.
7. Functional test extended and passing.

## Open questions

- Accepting workspace paths as positional args to `rm` (convenience beyond
  podman semantics)? Proposed yes.
- Should `ls` also show orphaned session state dirs (no pod)? Could be a
  `--state` flag or folded into `rm --all` only.
- `--pod-id-file`: skip (podman parity is not valuable here).
- Listing at the container level (like `podman ps`) instead of pods?
  Pods are the cleanup unit; containers die with the pod. Skipped.
